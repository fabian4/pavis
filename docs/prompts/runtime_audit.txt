============================================================
RUNTIME-SPECIFIC HARD BOUNDARIES
============================================================

`crates/pavis` (runtime) MUST:
- act purely as a data-plane runtime
- consume ONLY validated artifacts (e.g., from pavis-pvs / pavis-core)
- treat configuration as immutable snapshots
- execute routing, matching, and forwarding logic efficiently

`crates/pavis` MUST NOT:
- parse YAML / JSON / xDS / serde-based configs
- perform semantic validation already handled by core
- apply defaults or inference logic
- mutate configuration in-place
- depend on control-plane or relay internals
- perform inbound TLS termination (out of scope)
- implement inline certificate logic (not supported)

Supported features (MUST NOT be flagged as missing):
- Routing actions: Redirect, Direct Response
- Rewrite support except regex+prefix match combination
